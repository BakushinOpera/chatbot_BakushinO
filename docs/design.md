# Phal 当前设计

> 这份文档描述**现在实际是怎么做的**。每次实现完一个变更，同步改这里；和需求文档、计划文档不一致时以这里为准。
> 数字都是默认值，几乎都能在设置页改（登记在 `pj1/app/registry.py`，每项有说明）。称呼：「你」= 用户，「她」= Phal。

---

## 1. 整体框架

```
pj2（Electron 桌面外壳）
  └─ 启动打包好的后端（sidecar），窗口里打开网页
pj1
  ├─ app/        FastAPI 后端（Python）：聊天、上下文、她的生活、各子系统
  ├─ web/        原生 HTML/CSS/JS 前端（无框架、无构建步骤）：聊天页、设置页、房间、阅读器、账本、小本子……
  ├─ tests/      每个系统一个 *_test.py（假模型 / 临时库，不碰真实数据）
  └─ data/       运行时数据（不进仓库）
assets/          房间素材：manifest.json（程序读的清单）、素材清单.md（人看的说明）、角色图、家具、道具
```

* **模型**：任何 OpenAI 兼容的 `/chat/completions`（默认 DeepSeek）。`app/llm.py` 统一调用。没配 key 时是离线演示模式（回复里打印拼好的上下文）。
* **数据**：
  * `data/chat.db`（SQLite）：聊天、归档、记忆、设置、状态、事件、账本、房间、意图……
  * `data/characters/<角色id>/`：按角色存的数据（现在只有小本子 `notebook.db`）。角色 id 来自 `config.CHARACTER_ID`（环境变量 `CHAT_CHARACTER`，默认 `phal`）。
  * `data/world/`：世界设定（作者层，见第 9 节）；`data/world/_places.json`：地点库。
  * `data/writing/`、`data/my_writing/`、`data/letters/`、`data/books/`：她写的、你写的、信、书。
  * `data/qq/qq.db`：QQ 自己的库（和本地完全隔离）。
* **角色配置**（`app/character.py`）：和「这个角色是谁」有关的都从这里读——名字、钱、你在她的世界里在哪、地点库骨架、价格的地点系数、天气默认坐标、QQ 里关于主人的默认介绍、世界专有词。默认值在 `DEFAULTS`（就是 Phal 的）；`data/characters/<id>/character.json` 里只写想改的项（旁边的 `character.defaults.json` 是默认值参考副本，改它不起作用）。
  * 提示词里写的「Phal」在发给模型前按角色换掉（`character.localize`，在 `llm._payload` 里统一做）；钱的单位在代码里用 `C.unit()`。
  * 挂载点：角色目录里放 `states.json`（加 / 改状态）、`events.json`（加事件类型），设置页自动出现它们的权重等设置项。
  * 人设：角色目录里有 `persona.md` 就用它当默认人设，否则用 `app/default_persona.md`（Phal 的精简版）。
  * 调好的设置值：角色配置的 `settings`（Phal 的就是你在设置页调过的那些：温度 2.0、模型、上下文条数、用词表、几个状态的时段、价格带……）当作设置页的默认值；第一次建库时也按它写初始值（`db.seed_settings`）。测试设 `CHAT_CODE_DEFAULTS=1` 只用代码里的默认值。
  * 公开版和你自己的 Phal：代码里的 `DEFAULTS` 是公开的现实世界版；想要别的设定（虚构世界），在本机的 `data/characters/phal/character.json` 里覆盖（这个文件在数据目录里，不进仓库）。
  * 称呼：代码里的提示词用「她」指用户，`localize` 只在系统写的部分（系统消息、最后一条里注入的那段）把「她」换成 `user_pronoun`；聊天消息本身不动。
  * 还没抽出去的：状态 / 事件的默认表、心情词默认值、气候表、房间素材。
* **设置**：所有设置项登记在 `app/registry.py`（键、分区、类型、默认值、范围、说明）；代码用 `registry.num()` / `registry.flag()` 读，所以代码默认值和设置页默认值是同一份。设置页按分区折叠，改完自动保存，可按项 / 按分区恢复默认。`.env` 只在库里没有这项时当初始值。
* **时间**：应用关着时她的生活**冻结、不补算**（例外：心情 / 精力按真实时间回落；零花钱、月末的信会补）。页面每 30 秒 tick 一次推进生活。
* **规则放在哪**：能用代码保证的规则由代码保证（概率、时段、价格范围、引用次数……），提示词只描述语气和内容。
  * 感叹号：所有给你看的文字都由代码去掉（聊天回复、主动消息 `life._say` / `reading.post_proactive`、批注 / 笔记、日总结、信、小本子、写作正文……，`guards.strip_exclaim`），提示词里不写「不用感叹号」；写作的去 AI 味检查也不再因为感叹号重写。
  * 引用次数：代码只认前 2 次引用（`burst.parse_quoted`），提示词里不写次数。
  * 价格范围、现实地名、字数上限仍写在提示词里：代码虽然兜底（重想 / 夹回 / 截断），但写清楚能少一次重试或少截坏句子。

## 2. 聊天

### 2.1 上下文怎么拼（`app/context.py: build_context`）

1. **稳定部分**：人设（`app/default_persona.md` / 设置里改过的版本，`{{current_date}}` 替换成今天）、世界设定总纲（常驻）、用词约束（禁词 / 常用词）、回复格式、理解对话的守则、房间有哪几处、你随时看得到她的账本等。
2. **易变部分**（放在后面的 user 消息里，利于提示词缓存）：当前时间、天气季节、她现在的状态 / 心情 / 精力 / 在哪、今天的小打算、生效中和刚没做到的意图、现在的限制、相关记忆（三类，按相关性 ≤ 12 条）、小本子检索结果（或审完抄写前的世界设定条目）、相关的房间物品 / 食物、写作手头的文档、她察觉到你改了小本子的提示……
3. **最近的聊天记录**：默认 24 条，另有字数预算 `context_char_budget`（12000 字，超了从最旧的丢）。
4. **这条新消息**（带引用）。

**整份上下文的总预算**（`context.fit_budget`，`context_total_budget` 默认 30000 字，0 = 不限）：拼好以后超了就按优先级裁——
1. 不裁：人设、稳定部分（总纲、人物、房间概况……）、这条消息；
2. 其次：状态、意图等易变部分和聊天记录（聊天记录从最旧的丢，至少留 `context_keep_recent` 6 条，开头不留孤零零的 AI 回复）；
3. 最先裁：世界条目 → 小本子 → 记忆（每块从末尾一行行去掉，只剩标题就整块不要）。
裁了什么记在 `meta["trimmed"]`，并写一行日志。

时间只注入、不判断：代码不写「用户问日期就……」，怎么用时间由人设里的规则决定。

### 2.2 记忆（`app/memory.py`）

* 三类：关于她（你）/ Phal 说过的 / 我们之间。每轮对话后后台提取一次（**和意图提取、小本子「她说的」合并成同一次调用**），去重，冲突以新的为准。
* 更早的历史不主动捞：模型需要时调 `search_history` 工具（`LIKE` 检索 `archive` 表）。
* `messages` = 当前会话窗口（开新对话会清空），`archive` = 全部历史（永不自动删）。删除一律两张表一起删。

### 2.3 连发和「正在输入」（`app/burst.py`）

* 任何时候都能发；每条一个气泡、带 id。发送 `POST /api/chat/send` 立即返回；她的回复、「正在输入…」、引用、丢弃的气泡从常开的推送 `GET /api/stream` 过来；前端在你打字时每 0.7 秒报 `POST /api/typing`（输入框有字或 1.5 秒内有按键算在打字）。
* 每个会话同一时间只有一个生成任务，新消息进队列，不会重复回复。
* **等待逻辑**：基础窗口 2 秒（她忙时 × 2）。她注意到你在打字的概率 70% × 状态系数（闲 1.2 / 一般 1 / 忙 0.5）：
  * 没注意到 → 窗口到就回，之后的算新一轮；
  * 注意到 → 你没在打就一起回；还在打就 30%（同样乘状态系数）先插一句短的（只回已发的），否则等你停手 2 秒（最长 15 秒）。
* **合并回复**：一轮几条带编号一起交给模型，插过的那句也给她看。可以引用时（两条 35%、三条以上 70%）按 `[{"quote": 编号, "text": ...}]` 输出；每轮最多引用 2 次，一条时不引用。纯文本的「【引用】#id」也认。
* 她正在发时你又发：50% 丢掉没发出去的、合并重写；否则先发完。已发出的不撤回。回复前你改 / 撤回了消息，以改后的为准。
* 条与条之间的停顿（她「正在输入…」）= 基础随机 0.5~1.2 秒 + 每字 0.05 秒（最多多 1.4 秒）（`guards.delay_for`，数字都在设置页）× 总倍率 `reply_delay` × 她这会儿闲 / 一般 / 忙（`type_k_*`：0.8 / 1 / 1.4）× 在外面（`outside_delay_mult` 2.5）；出戏不乘状态（`main.typing_scale`）。
* 设置页「连发和等待」有按当前参数实时算出的比例表。

### 2.4 回复后处理和兜底

* 感叹号换句号；按空行切成多条（单条 > 60 字截断，一次 ≤ 6 条）；禁词（`data/banned_words.txt`）命中重新生成 ≤ 2 次；默认温度 0.9。
* **【OOC】** 开头：不切分、不查禁词、不换感叹号、不进记忆，允许跳出角色。
* 模型可在回复末尾附结构化动作 `{"action": ...}`（`guards.extract_actions`，对你隐藏）：`add_item`（你送 / 寄她东西时**立刻**收下）。读书开始 / 停止走对话意图（见第 7 节）；只有对话意图关着时才用回复里的 `start_reading` / `stop_reading` 动作。
* 你编辑过的她的回复会作为风格范例；说话风格笔记从全部历史里学（每 30 条 AI 回复重学）。
* 心情同步（`app/moodsync.py`）：你说自己的心情时，先关键词筛，筛中的才多调一次模型确认类别，再按 50% 推她的情绪一下（冷却 10 分钟）。

## 3. 她的生活：状态机（`app/life.py`、`app/states.py`）

* 约 40 个状态（喝茶、看书、发呆、刷视频、打游戏、试图创作、写作业、做饭、出门吃饭、散步、逛街、和朋友出去、午睡、生病躺着……），每个状态在设置页可配：权重、持续时间、允许的时间段、天气条件、是否花钱、是否「在外面」。
* **选下一个状态**：权重 × e^(精力系数 ×（精力 − 0.5）× 2 + 情绪系数 × 情绪) × 各种倍率（小打算 × 2、灵感、意图……）。「软指定」（醒来泡茶等）也守时间段。
* **作息**（`app/daily.py`）：22 点睡、7 点起；睡着时不推进、不主动找你；半夜被叫醒会迷糊。睡前晚安。21 点日总结（晚间状态 + 一句话 + 小结，进日历）。
* **每天的小打算**：起床时定 1~2 个，被选中的概率 × 2，做够 10 分钟勾掉，没做完顺延 ≤ 2 天。
* **聊天时暂停**：你发消息后 2 分钟内她的活动暂停。
* **被打扰**：打游戏 / 刷视频 / 追剧时你来找，50% 先撒娇。
* **主动消息**：按触发顺序排队发（前一个最多等 2 分钟），每小时有上限；发时有系统通知。
* **「为什么」**（`app/whylog.py`，表 `why_log`，留 7 天，设置「状态与概率」里可关）：每次随机决定记一行——下一个状态（情绪 / 精力、基础权重 → 调整后、最终概率、其它候选；说过要做的、写作不顺换个事做也记）、这顿怎么吃（周末 / 下雨 / 心情差……和各吃法概率；照意图吃的也记）、今天的事（几件、每件的类型）、买东西（只记掷中了的：概率 = 状态 × 余额系数，再按类别权重）。指定的状态（做饭链、你叫她做的）不记。看的地方：状态栏旁的「为什么」按钮、设置页「生活事件 → 今天的计划」旁的按钮；接口 `GET /api/why?kind=`。
* **结果分档**（`app/behavior.py`）：写作（顺利 / 写了一点 / 卡住 / 不满意 / 删了重写）、读书（入迷 / 一些 / 读不进去）、做饭、出门（开心 / 一般 / 扫兴），按此刻的情绪、精力、灵感抽；只有约 40% 带情绪反应（`react_p_*`）。

## 4. 心情和精力（`app/mood.py`）

* **情绪 v**（−1~1）= 今天的基线 + 各次推动（半衰期 `mood_half_v` 90 分钟）。
* **精力 e**（0~1）= 一天的节奏（醒来 0.45 → 10 点 0.82 → 14 点 0.52 → 17:30 0.68 → 睡前 0.32）+ 昨晚睡眠 + 活动消耗 / 恢复（`state_de_*`）。
* **基线**（起床后第一次 tick）：昨天平均情绪 × 0.4 + 天气 + 季节 + 星期几 + 睡眠 + 昨天事件 + 随机；影响最大的一两项让模型写成「今天心情的原因」（也是日历那一句）。
* **心情词**：按 (v, e) 分四组（分界 v −0.1、e 0.55，带滞回）；换组或有事带来情绪时从那组随机取一个（词表在设置页，可带权重）。附加词（想念、嘴馋……）由情境挂一阵。同类事 3 天内反复，推动打折（× 0.6、× 0.36）。
* **表达**：上下文给「心情词（原因）；精力」，叮嘱用语气体现、不直说；你问到才直说；每轮 8% 可以顺口提。
* **灵感**（0~1.5，半衰期 18 小时）：看完书、发生事、雨雪、你来聊天会加；写作倍率 =（0.1 + 2 × 灵感）×（1 − 满足感）。
* **事件基调**：好事 / 平常 / 不顺用洗牌袋（12 张，3 : 1），同类 3 天内不顺过就不再抽到不顺。
* 节日当天心情有下限。

## 5. 吃饭和食物

* **饭点**（`app/meals.py`）：午饭 11:30~12:30 随机，晚饭 18:00 前后。吃法按权重：自己做 / 外卖 / 一个人出去吃 / 和朋友 / 和家人，受工作日、心情、天气、季节、余额、生病、家人出差、意图影响。菜名由模型写（现实地名检查兜底），几天内不重复。
* **和朋友吃**：75% AA、15% 朋友请、10% 她请。
* **在外面到饭点**：特地出门的在那边吃；平时在县城里出门的会被叫回家吃（要不要统一见 PROGRESS）。
* **家人出差**（`app/family.py`）：每月随机连着 2~3 天，这几天她在房间食物桌一个人吃。
* **食物**（`app/clutter.py`）：甜点 / 奶茶 / 零食 / 水果 / 饭菜，放书桌杂物区（≤ 6）或食物桌（≤ 10）；保质期按种类随机，过期的睡前清理时收掉。吃东西不是单独状态：在一些状态里按频率（每小时 0.35 次 × 心情越差 / 越累越想吃）边做边吃。

## 6. 零花钱和物价（`app/money.py`、`app/prices.py`）

* **钱**：每月 1 号发 1500 块，结余滚存，漏掉的月份补发。< 300 块算「紧」、< 100 块「很紧」：外卖 / 出去吃 / 消费概率乘 0.5 / 0.15，很紧不买大件。
* **消费**：每 20 分钟考虑一次；「花钱」的状态 30%、其它 5%；买什么受状态、心情、天气季节、余额影响；每天 ≤ 4 次，大件间隔 ≥ 3 天。约 35%（大件 70%）主动告诉你。会留下的东西进房间，零食奶茶进杂物区。
* **价格**（默认值在 `app/price_defs.py`，按浙江新昌物价，单位块，吃的按一人份）：
  * 27 个大类，每类「最低 / 常见低 / 常见高 / 最高」（草稿见 `docs/已完成的计划/价格带草稿.md`）。
  * 允许范围 = 价格带 × **档次**（路边摊 0.7 / 连锁 1 / 商场 1.3 / 高档 2.5）× **噱头**（网红、限定、IP 联动、稀有食材、被坑了）× **地点**（默认：新昌 1、嵊州 1、杭州 1.25、上海 1.5，来自角色配置）。游戏、内购。
  * 代码定买哪类、大概花多少、最多花得起多少；模型给东西 + 店名 + 大类 + 档次 + 噱头 + 价格；超范围重想一次，还不行夹回范围内（`money.settle_price`）。地点由她当时在哪决定。
  * 尾数：100 以下一半是 x.9，100 以上多是 199 / 268；内购只取 6 / 30 / 68 / 128 / 198 / 328 / 648。
  * 同店同物：第一次的价格为准，之后 60% 一样、其余 ±10%（记在小本子店铺条目里）。
  * 贵的东西，分享时可以自然说为什么贵。
* **账本页**：月余额、分类汇总、明细（含没告诉你的）、手动加扣。

## 7. 对话意图（`app/intents.py`）

* **提取**：每轮和记忆一起提取她的打算 / 答应你的事（表 `chat_intents`）：类型（吃饭 / 做事 / 买东西 / 吃房间里的东西 / 作息）、结构化内容、原话、生效时间（≤ 3 天）、强度（随口 / 答应了 / 很坚定）、来源消息、结果、原因。
* **执行**：不打断正在做的事，只影响接下来的随机决定；每个意图只判定一次。照做概率：随口 60%、答应 85%、坚定 95%；心情差 × 0.85、很累 × 0.85、下雨还要出门 × 0.75。冲突的出门类状态概率 × 0.3，真被拉出去就记「没做到」并写原因。吃房间里的东西会扣份数。
* **没做到**：原因进记忆和上下文；70% 主动提；没吃成的 40% 变成新意图（「留着当夜宵」）。
* **读书指令**（kind `read`）：你叫她读会儿书 / 休息一下，她答应了就是一条「读书」意图。提取完（回复后几秒到十几秒）马上按强度的概率判定：照做就开始 / 停下读书；没照做记原因（「拿起书又放下了」「又多看了一会儿」），按上面的规则可能主动提。读满了、书架上没书算没做到。她当轮就拒绝了的（30% 拒绝读书、刚拒绝过再磨减半）不会产生意图。
* **防乱许诺**：上下文写「现在的限制」（快睡觉、钱紧、书读满、爸妈出差、生病、东西过期）。
* 设置页「说过的打算」：概率、系数、最近 60 条意图列表。

## 8. 出门和地点（`app/places.py`）

* **地点库**（`data/world/_places.json`）：名字、种类（世界 / 国家 / … / 店 / 家）、上级、离家分钟数、权重、价格系数地点、她不知道、备注、预留坐标。骨架来自角色配置，默认：家 → 新昌 → 绍兴 → 浙江 → 南方 → 中国 → 世界，加嵊州、杭州、上海。地点只当地名用，不做地图。
* **目的地**：在外面的状态开始时代码定去哪：多数在县城，偶尔去隔壁（默认嵊州）；远的地方只在周末 / 和朋友时「特地出门」，时长拉到够来回 + 待 1.5~3 小时、21 点前到家。连着几个在外面的状态留在同一处；在外面到睡觉点算回家。
* 地点用于：价格系数、出门 / 回家的消息、事件和消费提示词、聊天上下文（在家不说）。

## 9. 世界设定（作者层）和小本子（她的认知）

### 9.1 世界设定（`app/world.py`，`data/world/`）

* 一类一个文件夹（「世界常识」……）。`_总纲.md` 常驻上下文（≤ 1800 字）；其它文件 / `## 小节` 是条目，文件名 + `关键词：` 行命中才带（≤ 3 条、每条 ≤ 1000 字）；`_提示.txt` 是这一类的口吻提示。
* `## 她不知道` 小节只给作者层用，不进她的任何上下文、不被抄写。
* 世界设定统一从 `world.py` 读：条目 / 总纲（`load` / `match`）、条目文件列表（`entry_files`，初始抄写用）、某类的文件名（`category_titles`）、地点库文件（`read_places` / `write_places`）。总纲字数、条目字数、一次最多几条在设置页「世界」。世界库和 Phal 设定冲突时保留 Phal 的。

### 9.2 小本子（`app/notebook.py`、`app/notebook_write.py`）

* **是什么**：她自己认知中的世界，可能有误解。按角色存 `data/characters/<id>/notebook.db`，每次改动导出 Markdown 到 `notebook_export/`。不记人（人在人物档案里）。
* **章节**（可在设置页改）：地方、店铺、物价印象、她说的（准确）；吃的、听说的事（会夸张）。
* **条目**：标题（同章不重复）、关键词、正文、追加、结构化信息（店铺：东西、价格、次数）、可信度（她的看法 / 已确认）、锁定、来源、地点、状态（待审）。每次改动留快照，可找回。
* **你改**：你建 / 改过的条目自动锁定、改过的片段标色；锁定的她只能在末尾追加（存储层拦住）。
* **她写**（所有写入走 `notebook.her_write`：同标题 / 标题互相包含 / 关键词重合多就合并）：
  * 第一次去的店：吃饭 / 消费那次调用顺便给印象（0 次额外调用），建条目并登记进地点库；
  * 第一次去的地方：建空条目，晚上写；
  * 你讲的世界上的事：和记忆同一次提取，进「她说的」；
  * 每晚整理（日总结后一次）；每周整理（1~3 次调用，只动没锁定的，合并 / 建议删的只标出来等你决定）。
* **去老店**：这一带有去过的店时 60% 去老店（带上次的东西、价格、印象）。
* **读**：聊天（你这条 + 最近三轮，≤ 4 条）；吃饭、消费、事件、出门（≤ 3 条）。初始抄写审完之前聊天仍直接读世界设定条目，审完只读小本子（总纲照旧常驻）。
* **她察觉修改**（默认关，10%）：你改了内容，下次聊天时可能随口提一句「原来记错了」，只一次。

## 10. 生活事件（`app/events.py`、`app/event_defs.py`）

* 每天起床后定今天几件（0 件 40%、1 件 40%、2 件 15%、3 件 5%），每件抽时间段和类型；到点检查条件，不满足顺延一次再作废。外出回来 50% 发生一件。
* 类型：家人、朋友（只用档案里定稿的）、路人、物品、网络、意外小事、身体、季节、家里、钱。权重 / 时段在设置页。
* 内容由模型按基调写，写进事件日志、记忆、人物档案；50% 主动告诉你，没告诉的不进日总结但影响心情。
* **生病**：平时每天 1.5%、季节交替更高、降温那天 8%，每次 2~3 天。

## 11. 读书、写作、信

* **书架 / 阅读器**：epub / txt / pdf（含扫描版图片书），双页翻页、目录、书签、搜索、画笔。她只读书架上真实的书：每读 2200~3400 字喂一次模型，产出批注（引用必须和原文一字不差）、笔记、分享；每天读书上限 30 分钟，你叫她读也可能被拒绝（30%）。批注像手写在页边。
* **写作**（`app/writing.py`）：她的文档在 `data/writing/`（一份 ≤ 1 万字），由灵感驱动；挑文档（最近那份 60%）、挑段落（另起一段 25%）；每份文档有故事笔记；去 AI 味检查；模仿「我的文字」的笔触。说要写哪份后 12 小时内接着写那份。你改了她的文档，她会察觉，25% 坚持自己的版本撤回。
* **月末的信**（`app/letters.py`）：每月最后一天日总结后写一封，存 `data/letters/`，只读；写之前汇总这个月；错过的补写 ≤ 3 个月。

## 12. 房间（`web/room*.js`、`app/room.py`、`assets/manifest.json`）

* 一份灰模场景两个视角：房间视角（等距）和书桌视角（透视）。画风 B（贴纸白边）默认，A（水彩）保留。
* 物品：名称、分类、位置、来源、备注；书由参数决定外观（书脊和封面同一组参数）；书架 50 本 → 地上 20 本 → 收纳篮。
* 角色：Q 版图按状态走到对应位置（不穿家具的路线），坐 / 躺 / 站各有图；被家具挡住时家具半透明。姿势调试器 Ctrl+Shift+P。
* 窗外天气：按钟点 + 她那边的天气 + 日出日落画天空、雨雪、闪电；室内光照；夜里暗光。渲染精度在设置页。
* 杂物区（书桌）和食物桌放食物，书桌上的笔记本点开是小本子。

## 13. 其它

* **天气**（`app/weather.py`）：她那边和你那边两处，联网用 Open-Meteo（只发经纬度），否则按每月气候表模拟；真实地名不进提示词。
* **人物档案**（`app/people.py`）：爸妈 + 模型生成后你采用的朋友；提到人只能用档案里的。
* **节日**（`app/festivals.py`）：当天主动祝福、心情有下限。
* **日历**：前天~后天四格 + 月历；任务（主要 / 次要、拖延天数、重复、红绿章）；Phal 每天的心情一句话。
* **QQ**（`app/qq/`，NapCat / OneBot v11）：主人私聊 + 白名单群。对本地库只读（`mode=ro`），QQ 的数据在 `data/qq/qq.db`，不进她的记忆和状态。群聊有回复概率闸门、频率上限、批量窗口、信任分级（对别人只说模糊版）、静默口令、群友印象、模拟群聊。设置在 QQ 页，不在统一设置页。

* **运行开销**（`app/usage.py`，设置页「模型与记忆 → 运行开销」）：每次调模型记一行（用途、耗时、输入 / 输出 / 缓存命中 token、成没成功），表 `llm_usage`，留 7 天。用途按调用 `llm` 的模块名推（不用调用方传）。聊天开始生成时 `usage.start_round()` 设一个 contextvar，这一轮里起的后台任务（回复后的记忆 / 意图提取）继承它，所以算在同一轮；她自己过日子的调用算「后台」。流式回复靠请求里的 `stream_options.include_usage` 拿用量（个别接口不认可以关掉，只记次数和耗时）。设置页显示最近 10 轮 + 今天的总量和后台部分；接口 `GET / DELETE /api/usage`。
